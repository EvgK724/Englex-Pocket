# Englex → Englex Pocket

Синхронизация добавляет новые записи личного словаря Englex в `dist/dictionary.json`.
Для мониторинга используется ежедневная задача ChatGPT в 23:45 (Asia/Yekaterinburg)
через авторизованный браузер;
этот репозиторий сам не входит в Englex и не хранит пароли, cookies или токены Englex.
Публикация `main` запускает существующий GitHub Pages workflow.

## Перенос записей

1. Открыть Englex → «Словарь» → «Весь словарь» в авторизованном браузере.
2. Читать английский текст, исходный перевод и дату из видимой таблицы. Список
   подгружает более старые записи при прокрутке вверх. Проверить весь период
   после предыдущего импорта, включая дату его последней записи: не ограничиваться
   первыми 20 строками. Первоначальная граница — 5 сентября 2026 включительно;
   историческую коллекцию до этой даты заново не импортировать.
3. Подготовить временный JSON-массив с полями `word`, `translation`, `ipa`, `kind`,
   `added`, `lists`. Дата — `YYYY-MM-DD`. Неизвестные IPA и списки — пустые строки.
   Категория приложения — `word`, `collocation` или `phrasal`; если Englex не
   показывает категорию, это наша классификация, а не данные источника.
   Не исправлять исходный перевод без отдельного запроса пользователя.
4. На актуальной версии репозитория выполнить:

   ```sh
   node scripts/import-englex.mjs /path/to/englex-new-words.json
   node --test scripts/test-import-englex.mjs
   node scripts/check-static.mjs
   ```

5. Если `changed` равно `false`, коммит не нужен. Иначе сохранить только результат
   импорта в GitHub и дождаться успешной публикации. При изменении ветки другим
   процессом повторить импорт на новой версии; не использовать force push.

Импорт сохраняет все существующие карточки и их идентификаторы, отбрасывает
повтор той же пары «слово + перевод», а новое значение уже имеющегося слова
добавляет отдельной карточкой и отмечает в отчёте. Обновления существующих
переводов и удаления из Englex автоматически не применяются. Проверка защищает
исходные 8 132 карточки и проверяет новые данные до публикации.

## На телефоне

Приложение запрашивает свежий словарь при запуске, возвращении на экран,
восстановлении соединения и раз в пять минут, пока оно открыто. Выбранная
карточка, избранное и прогресс сохраняются. При ошибке обновления уже открытая
коллекция остаётся доступной. В меню ровно три голоса: «Ryan», «Choni» и «Doris». Ryan выбран по умолчанию;
при первом обновлении прежняя настройка голоса однократно переключается на Ryan.
Дальнейший ручной выбор сохраняется. Выбор применяется ко
всей коллекции; записи одного голоса не подменяются другим. Если запись выбранного
варианта отсутствует, приложение показывает это и предлагает выбрать другой голос.
Прежние записи AI Voice сохраняются.

## Озвучка

Голос «Choni» — выбранный пользователем вариант A для всей коллекции. Профиль `a-v1` использует
прежний Fish voice ID `089f2e853e064d6fb15f5b5882914b52`, только бесплатный
`s2.1-pro-free`, temperature `0.3`, cue `[Native British English pronunciation, clear neutral English vowels] `
и прежнюю обработку `--denoise`. Точная одобренная запись `recover` копируется
из варианта A без повторного синтеза. Файлы пишутся в `dist/audio/fish-chonishvili-a-v1/`,
индекс — `dist/fish-chonishvili-a-v1-index.json`.

Изменение `dist/dictionary.json` запускает подготовку только отсутствующих записей A.
Одноразовый запуск всей очереди: коммит начинается с
`Run Chonishvili A dictionary [fish-a-v1]` или workflow Fish, voice `a`, mode `full`.
Готовые записи публикуются порциями; продолжение после ограничения времени возможно
только при подтверждённом прогрессе, максимум восемь раз. Ошибки API, квоты,
авторизации или публикации не вызывают автоматического повтора и не включают платный engine.
Секрет Fish остаётся только в GitHub Actions. Старые MP3 и индексы сохраняются,
но старые голоса и экспериментальные пробы не предлагаются в интерфейсе.

### Очистка Choni

По запросу пользователя 20 сентября 2026 года Choni воспроизводит более тихую
производную одобренного A. Исходные MP3 профиля `a-v1`, включая `recover`,
остаются побайтово неизменными. Это обработка готового звука, без повторного
синтеза, передачи данных новому провайдеру, сдвига высоты или темпа.

`scripts/clean-choni.py` создаёт `dist/audio/fish-chonishvili-a-clean-v1/`
и `dist/fish-chonishvili-a-clean-v1-index.json`. Профиль `a-clean-v1`
указывает `sourceProfile: a-v1` и исходный Git blob SHA для каждого ID.
Щадящее спектральное шумоподавление и плавное ослабление тихого фона
не повторяют прежний EQ и не срезают низкую основу голоса.
Результат сохраняется в MP3 mono96кбит/с; проверяется полное декодирование,
точная длина, громкость и сохранность источника.
Уменьшение фонового шума не означает доказанного устранения всех артефактов
синтеза во время речи.

Workflow `choni-clean.yml` дополняет производные после успешного
`Prepare Fish voice library`, при ручном запуске или изменении самого workflow.
Он работает только с отсутствующими производными, сохраняет все прежние файлы,
публикует их на свежем main без force push и запускает Pages.
Повторная обработка очищенных файлов не допускается. При изменении исходного
blob остановиться и проверить причину; не подменять производную автоматически.
Приложение предпочитает очищенный MP3. Пока он не готов, доступен исходный A;
при ошибке загрузки очищенного файла пользователь видит сообщение и может
отдельным нажатием прослушать исходный Choni. Другие голоса не подставляются.
Перед сообщением о полном охвате сверить текущий словарь, все ID чистого индекса,
наличие MP3 и итоговую публикацию; отчёт процессора относится к его исходному
снимку словаря и сам по себе не исключает параллельного добавления карточек.

### Оригиналы Englex AI


Исходные записи Englex AI доступны через динамик с пометкой AI
в авторизованном личном словаре. Сохранить аудиофайл через доступный интерфейс
браузера; сопоставить точный английский текст с текущими карточками. Не использовать
скрытые API или перенос сессии. Временные `blob:` URL, cookies и токены не публиковать.
Временный локальный JSON: `[{"word":"точный английский текст","file":"/path/to/original.mp3"}]`.
Выполнить `node scripts/import-englex-audio.mjs /path/to/captured-audio.json`.
Он сопоставляет все значения точного слова, сохраняет текущие записи и сообщает конфликты;
существующие разные MP3 не перезаписываются. Неизвестные слова не создают карточек.
MP3 хранятся в `dist/audio/englex-ai/`, индекс — `dist/englex-ai-index.json`.
При синхронизации новых карточек сохранять доступную исходную AI-озвучку тем же
способом; отсутствие доступной записи не блокирует импорт словаря.
Для пакетной публикации исходных MP3 можно подготовить
`.englex-audio-import/batch.json`: `{ "version": 1, "recordings": [{ "word": "...", "audioBase64": "..." }] }`.
Содержимое — только фактически сохранённые аудиофайлы Englex AI, до 1000 записей
и 20 MiB на пакет. Нельзя включать URL, токены, пользовательский профиль и переписку.
Коммит начинается с `Import original Englex AI recordings [englex-ai-v1]`.
Workflow читает пакет именно из этого коммита, сливает его с актуальным словарём,
сохраняет параллельные записи A и запускает Pages. При конфликте исходных MP3
не заменять существующую запись автоматически — сначала проверить точное соответствие слову.


Список наблюдавшихся, но ещё не перенесённых кандидатов сохранён в
`.englex-audio-import/backlog.json`. Он неполный: более ранняя история ещё не
просмотрена целиком. Перед сохранением повторно проверить точный текст строки
и пометку AI; после выбора динамика сверить текст владельца аудиоэлемента.
Похожие результаты поиска нельзя выбирать по первому совпадению. В пакет
включать только действительно сохранённые и проверенные локальные MP3.
Озвучку существующих карточек можно дополнять независимо от исторической
границы импорта новых слов; сам словарь и идентификаторы при этом не менять.

Покрытие каждого из трёх голосов отображается в приложении отдельно.


## Дополнение Doris (мягкого AI Voice)

Пользователь разрешил синтез недостающих записей для всех текущих и новых карточек.
Индекс `dist/audio-index.json` подтверждает исходный провайдер `AI Voice Generator`
и голос `delicate`. Существующие MP3, индексные метаданные и `voiceOverrides`
сохраняются, включая ранее выбранную отдельную запись `signature`.

После импорта словаря сравнить все текущие ID с актуальным `audio-index.json`.
Для отсутствующих записей вызвать доступный connector
`ai_voice_generator_create_audio` с `voice_id: "delicate"` и полным английским
текстом карточки (`speechText(word)`: убираются только фигурные скобки разметки).
Перевод, IPA и дату в синтез не передавать. Для короткой фразы до 500 символов
`preview_transcript` должен в точности равняться полному `transcript`: тогда
preview MP3 содержит всю фразу. Более длинную запись брать из полного результата,
не обрезать до preview. Сохранить фактический MP3 и проверить декодирование.
Прямой временный URL результата служит только для сохранения файла и в репозиторий
не переносится. Недоступный connector или квота не разрешают подменять голос.
GitHub Actions самостоятельно не вызывает этот connector; запись готовит
авторизованный процесс синхронизации, публикацию выполняет workflow.

Подготовить `.soft-audio-import/batch.json`:
`{"version":1,"provider":"AI Voice Generator","voice":"delicate","recordings":[{"id":"ID карточки","word":"точный исходный текст dictionary.word","audioBase64":"фактические байты MP3"}]}`.
Идентификатор и `word` в пакете должны соответствовать текущему словарю без правки
его текста. Пакет ограничен 1000 записями, 20 MiB и 1 MiB на один MP3.
Коммит начинается с `Import soft AI Voice recordings [soft-ai-v1]`.
Workflow проверяет весь пакет, дописывает только отсутствующие MP3 и ID
в актуальный `audio-index.json`, сохраняет остальные поля и параллельную генерацию A,
публикует результат через Pages. Проверить успешное завершение workflow, наличие
добавленных ID и фактическую публикацию. При изменившемся main повторить слияние;
не использовать force push. Отчёт об успехе озвучки требует реального покрытия ID.

## Источник и дополнение Ryan (Englex AI)

Публичный код Englex использует Microsoft Edge TTS; в поставляемом синтезаторе
явно задан британский мужской `en-GB-RyanNeural`. Источники и границы проверки
описаны в [docs/englex-ai-source.md](docs/englex-ai-source.md).
20 сентября 2026 года пользователь подтвердил полное совпадение Ryan с Englex
после прослушивания и разрешил передачу Microsoft/Bing английского текста
текущих и будущих карточек для проверки и генерации недостающих записей.
Не заменять этот профиль приблизительно похожим голосом.

Новый синтез имеет отдельные `dist/englex-ryan-index.json` и
`dist/audio/englex-ryan/`. Исходный Englex индекс не переписывается; оригинал
всегда имеет приоритет для той же карточки. Меню остаётся из трёх вариантов.
Новые MP3 учитываются только после успешного декодирования и сохранения;
полное покрытие проверяется объединением исходных и сгенерированных ID.

Генератор `scripts/generate-englex-ryan.py` использует `edge-tts==7.2.8`,
только `en-GB-RyanNeural`, обычные скорость, высоту и громкость. Передаётся
только английский текст, без переводов, IPA или иных данных Englex.
Нельзя отключать проверку TLS, обходить ограничения сервиса или автоматически
переходить на платный Azure. Ошибка доступа не разрешает подмену голоса.

Workflow `englex-ryan.yml` автоматически дополняет отсутствующие записи при
изменении `dist/dictionary.json`; изменение самого workflow также запускает
начальную очередь. Синтезируется только английский текст карточки. Готовые файлы
публикуются порциями с актуальным main без force push. Продолжение допускается
только после продуктивного завершения по лимиту времени, максимум восемь раз.
При ошибке сервиса автоматического продолжения и подмены голоса нет. Проверять
результат Actions, union покрытия двух Englex индексов и успешную Pages-публикацию.

`english-ai-preview.html` содержит подтверждённый образец Microsoft Ryan и
исходный Englex AI. Ранее подготовленный файл `clear` сохранён, но не используется
для карточек и не является четвёртым вариантом.

## Ошибки доступа

Если Englex завершил сеанс или не показывает словарь, не заменять коллекцию
пустыми данными и не сообщать «новых слов нет». Задача должна уведомить о
необходимости восстановить доступ. Вход выполняется через защищённую форму,
пароль не передаётся в чат или репозиторий.
